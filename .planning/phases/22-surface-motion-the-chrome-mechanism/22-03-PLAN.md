<objective>
Hoist the one-shot `beforeinstallprompt` capture out of component-local state and into a module-level
singleton (D-33), and fold `isStandalone()` into the same store (D-36).

Purpose: **NAV-06 is dead on Android without this.** `REQUIREMENTS.md` §Verification Notes flags it
directly — the event is one-shot and fires early, but `useInstallState()` captures it in
`useRef`/`useState` per hook instance, so the Settings install section (plan 22-06), mounted long
after the event fired, never sees it. Hoisting also fixes a latent bug that ships today: `AppMenu` and
`InstallBanner` each register their own listener with their own `deferredRef`, so they can disagree
about `canInstall`, and each calls `isStandalone()` independently.

Output: `pwa/install/installStore.ts`, a rewritten `useInstallState()` with an unchanged public shape,
and `installStore.test.tsx`.

`InstallBanner` is left completely as-is (D-37): NAV-05 names the instructions and the menu row, not
the banner, and the banner is what gets a new user to the relocated section. It gets a free
correctness win from the shared capture with no change of its own.
</objective>

## Planner decisions

**RESEARCH Open Question 5 — "do the existing install tests survive a module-level singleton?" — Yes,
both survive unmodified. Audited this planning pass:**

- `packages/app/test/platform.test.ts` imports and calls `isStandalone()` / `isIosSafari()`
  **directly**. `platform.ts` is not changed by this plan, so that file is unaffected. Do not edit it.
- `packages/app/test/installBannerVersion.test.tsx` renders `InstallBanner`, which calls
  `useInstallState()`. Module-load evaluation of `isStandalone()` reads `window.matchMedia`, and
  `packages/app/test/setup.ts` **already defines `window.matchMedia` returning `matches: false`** for
  every app test, with Vitest running `setupFiles` before the test file's own module graph is
  imported. So module-load `isStandalone()` resolves to `false` (not installed) and `isIosSafari()` to
  `false` (jsdom's default UA) — exactly the state that file's cases expect. Its own per-file
  `stubMatchMedia()` becomes redundant but stays harmless. Do not edit it.

**Consequence:** because the platform reads are frozen at module load, a test that needs
`isIos: true` or `isInstalled: true` must override them without `vi.resetModules()` gymnastics across
two files. Therefore `__resetInstallStoreForTests` takes an **optional overrides argument**.

**RESEARCH Open Question 6 — "should the store also listen for `appinstalled`?" — YES, add it.**
D-36 settles that `isStandalone()` need not be re-evaluated, because the *current page* never
transitions into standalone mode; `appinstalled` is a **different** event that fires in the current
page after an in-page install, so listening for it does not contradict D-36. Three lines (clear
`deferred`, set `installed = true`, `notify()`), and it makes NAV-05's "hidden once the app is
installed" take effect within the session that performed the install — which is precisely what the
plan-22-09 Android device test needs to observe without a reload. Cost of getting it wrong is zero:
the worst case is that a section hides one reload earlier than it otherwise would.

Module state:
  - `deferred: BeforeInstallPromptEvent | null` — move the `BeforeInstallPromptEvent` interface here
    **as-is**, keeping its "not in lib.dom.d.ts — declared locally rather than pulling a types package
    for two methods" comment with it.
  - `listeners: Set<() => void>`.
  - `installed` and `ios` — evaluated **once at module load** (D-36), each guarded by
    `typeof window === "undefined"` so an import-time evaluation cannot throw. A page cannot transition
    into standalone mode (an install opens a new instance), so re-evaluating buys nothing; what matters
    is that both gated surfaces read the **same** value. `installed` is a mutable `let` (not a `const`)
    because the `appinstalled` listener below flips it.
  - `snapshot: InstallSnapshot` — **a cached module variable, recreated ONLY inside `notify()`.**
    React 19.2.7 detects an uncached object `getSnapshot` and reports "The result of getSnapshot should
    be cached to avoid an infinite loop"; both existing stores in this codebase already model the fix.
    Never build the object inside `getInstallSnapshot()`.

Exports:
  - `subscribeInstall(listener)` → unsubscribe, same shape as `bottomOverlayInset`'s `subscribe`.
  - `getInstallSnapshot()` → a one-line `return snapshot;`.
  - `getInstallServerSnapshot()` → a module-level frozen constant (the app has no SSR, so this is
    defensive, but React 19 warns "Missing getServerSnapshot" without it — both existing stores provide
    one).
  - `promptInstall(): Promise<void>` — no-op when nothing is captured; otherwise `await d.prompt()`,
    `await d.userChoice`, clear `deferred`, `notify()`. The `notify()` is the D-33 bug fix: every
    subscriber loses `canInstall` together instead of only the one that fired it.
    **`prompt()` is gesture-bound — preserve the shipped shape with NO `await` before it.** The current
    `useInstallState.promptInstall` calls `deferred.prompt()` with nothing awaited first; inserting any
    `await` ahead of it (an analytics call, a Dexie read, a `notify()` round-trip) breaks the
    user-gesture chain on Chromium and the prompt silently never appears — indistinguishable from the
    very bug D-33 is fixing. Put that warning in the function's doc comment.
  - `__resetInstallStoreForTests(overrides?: { isIos?: boolean; isInstalled?: boolean }): void` —
    mirrors `__resetBottomOverlayInsetForTests` (clear `deferred`, clear `listeners`, rebuild the
    cached snapshot) and additionally lets a test pin the two module-load platform reads. Document it
    as test-only in the sibling store's one-line comment style.

Listeners, at module scope, inside a `typeof window !== "undefined"` guard:
  - **one** `window.addEventListener("beforeinstallprompt", …)` that calls `event.preventDefault()`,
    stashes the event and `notify()`s;
  - **one** `window.addEventListener("appinstalled", …)` that clears `deferred`, sets
    `installed = true` and `notify()`s. Comment why this does not contradict D-36: D-36 is about
    `isStandalone()` not needing re-evaluation because the current page never *becomes* standalone;
    `appinstalled` is a different, explicitly-fired event that tells the current page an install
    completed, and honouring it is what makes NAV-05's "hidden once installed" true within the session
    that performed the install.

Add a comment recording why the capture timing is safe: this module is imported transitively during
initial bundle evaluation (`App.tsx` → `AppMenu`/`InstallBanner` → `useInstallState`), i.e. before
`createRoot().render()`, and `beforeinstallprompt` fires after the manifest and service worker are
evaluated — strictly later. The one-shot event cannot be missed. If any consumer is ever made a lazy
import, add an explicit side-effect import in `main.tsx`.

Do **not** hoist `dismissed`/`dismiss` — see Task 2.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → app | The `beforeinstallprompt` event object is supplied by the user agent, not by a remote party. It is stashed and later invoked; no field of it is read, rendered, persisted or parsed. `appinstalled` carries no payload at all. |
