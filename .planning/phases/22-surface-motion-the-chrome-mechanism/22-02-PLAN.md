## ⚠ Pitfall 14 — the defect this plan exists to avoid. Read before writing a line.

**An exiting `AnimatePresence` child renders from a FROZEN React element.** `AnimatePresence` keeps
exiting children in its own `renderedChildren` state — the elements exactly as they were last created
**while present**. Motion's own docs say it verbatim: exiting children "cannot receive prop updates
because when a component is removed from the React tree … its props can no longer be updated."

So anything computed in `Sheet`'s render from the `open` prop —
`aria-hidden={open ? undefined : true}`, `pointerEvents: open ? undefined : "none"`,
`onClick={open ? onClose : undefined}`, `onAnimationComplete={() => { if (open) … }}` — is baked in
at `open === true` and **stays that way for the entire exit window**. D-19 items 3 and 4 silently
never happen, and **every test written against the open state still passes.**

Probe P2 in `22-RESEARCH.md` reproduced exactly this. Probe P1, with the identical structure but the
values derived from `useIsPresent()` inside the child, produced `aria-hidden="true"` and
`pointer-events: none` **synchronously**.

**Rule for this plan: every presence-dependent value lives inside `SheetSurface` and derives from
`useIsPresent()`. Nothing derives from `open` except `useFocusTrap`'s and `useDialogDismiss`'s
`active` argument — and those are correct precisely because `Sheet` itself is not the frozen
element.** `useIsPresent()` also self-corrects on re-open (D-22's interrupt-and-reverse), because
`PresenceChild` re-creates its context value whenever `isPresent` flips and React re-renders every
consumer of that context.

**Corollary for testing:** a hand-rolled `AnimatePresence` double that re-renders `children` fresh
would show the attributes flipping correctly **even against the broken prop-derived code**, i.e. it
would make the D-20 test pass against the defect. That is worse than no test. Task 3 uses the real
library.

Three changes to `packages/app/src/components/a11y/useFocusTrap.ts`. This is a **re-timing, not a
rewrite** — the teardown already fires at close-start today, because React runs an effect's cleanup
whenever a dep changes, not only on unmount, and `Sheet` passes `active: open && modal`, which is
derived from `open` and never from presence. Probe P1 confirmed it empirically: `#app-content.inert`
was `false` and `document.activeElement` was the trigger synchronously after the close, while the
sheet node was still in the DOM.

1. **Switch `useEffect` to `useLayoutEffect`.** React applies DOM attribute updates during the
   commit's mutation phase but runs passive-effect cleanups after paint. A layout effect's destroy
   runs synchronously inside the same commit, which is the safer contract to write down for the
   ordering Pitfall 4a describes (focus restore must complete before `aria-hidden` lands on the
   exiting card).

2. **Guard the release with a per-instance `releasedRef`.** `setRootInert(false)` decrements a shared
   ref count and guards underflow only at zero. With two sheets open the count is 2; if the release
   ever runs twice for the same hook instance the count drops 2 → 0 while the other sheet is still
   open, and the background becomes interactive underneath an open modal. Add a `useRef<boolean>` set
   `false` on activate and `true` on release, and make the release a no-op when already `true`. This
   is invisible in a single-sheet test.

3. **Split the `initialFocusRef` focus out of activation (D-27) and return it.** Change the hook's
   return type from `void` to `{ focusInitialTarget: () => void }`. On activate, focus
   `focusables()[0] ?? container` — **never** `initialFocusRef`; that keeps focus inside the trap
   from frame 0, so a keyboard/VoiceOver user is not parked on a now-`inert` trigger for 200ms.
   `focusInitialTarget()` focuses `initialFocusRef.current` if one was supplied, is a no-op
   otherwise, and is safe to call more than once. Make the returned function referentially stable
   (`useCallback` or a ref-backed closure) so `SheetSurface` can pass it into a `motion` callback prop
   without churning identity every render.

Add a source comment on the effect recording **the invariant to preserve**: `active` is a function of
`open`, never of "is this still in the DOM". Making the hook presence-driven would defeat the whole
close-start contract.

The hook's 16 consumer files are unaffected — nothing but `Sheet.tsx` calls it.
