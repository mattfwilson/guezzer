## Planner decision — what the last-payload ref is actually for

**Read this before writing the ref, because the obvious rationale is wrong.** The retained exit frame
does **not** render from `shown`. `AnimatePresence` keeps the `SheetSurface` **element** captured on the
last render where `open` was true, with frozen props and frozen closures (`22-02-PLAN.md` §Pitfall 14).
The `children` JSX these components build on the closing render is handed to `<Sheet open={false}>`,
which renders nothing at all — so that JSX is constructed and immediately discarded.

That leaves the ref one real, narrow job: **the closing render must not throw while constructing the JSX
it is about to discard.** Both components dereference their payload for the `ariaLabel` and throughout
the body, and on the closing render the prop is already `null`.

**Hold the last non-null payload in a `useRef`** and derive `shown` from it. Two rules:
  - Update the ref on every render where the prop is non-null, then derive
    `payload ?? lastPayloadRef.current`. Never write to a ref inside an effect for this — the closing
    render must already have the value.
  - If both are null (first mount, before anything was ever opened), render `<Sheet open={false}>` with
    an empty body and a safe fallback `ariaLabel`. `<Sheet open={false}>` produces **zero DOM nodes**
    (plan 22-01's `AnimatePresence`-with-no-child path), so an always-mounted closed sheet costs nothing.

**Do not move any state out of these components.** `TrailNodeSheet` keeps its `searchOpen` /
`confirmingDelete` `useState` and its `close()` reset; `WhyDetail` stays stateless. The conversion is a
render-shape change, not a state refactor.
