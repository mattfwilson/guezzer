<objective>
Two pieces of dex-drill-in work that share one file.

**CR-02 (Tasks 1–2):** `SetlistView`'s loading state is an unrecoverable `aria-modal` trap.
`useLiveQuery(() => db.archiveShows.get(showId), [showId])` returns `undefined` **both** while
resolving and when no row exists, and the comment at `SetlistView.tsx` ("hasn't resolved *yet*")
encodes the assumption that the second case cannot happen. When it does, the user gets a blank
full-screen `role="dialog" aria-modal="true"` with no control of any kind — and because its
`aria-label` is `copy.albumBack`, VoiceOver announces the blocker as **"Back"**, the one thing it does
not offer. Fixed by **distinguishing the two states**, not by bolting a close button onto one branch
that serves both. **Explicitly NOT the fix:** migrating this surface onto `<Sheet>` — that
contradicts D-16 and Phase-21 D-22. It stays hand-rolled.

**The one sheet conversion (Task 3):** `22-RESEARCH.md` §Open Question 1 establishes that **every
`fullscreen` `<Sheet>` consumer is in the unmount-driven set**, so without one conversion D-26's
fullscreen exit fade has no live consumer and cannot be device-verified at all. The settled scope
decision is to convert **only** the sheets D-21's on-device sample needs; the addendum names
`DexView`'s trophy case as the cheapest fullscreen candidate — one guard expression. Everything else
stays a documented seam.

Output: an honest loading/missing split with a real exit, and one prop-driven fullscreen sheet.
</objective>

## Planner decisions

**Which pending-sentinel shape (RESEARCH §Pattern 10): shape (b), object-wrap the querier.**
`useLiveQuery(async () => ({ row: await db.archiveShows.get(showId) }), [showId])`, with
`loading = wrapped === undefined` and `missing = wrapped !== undefined && wrapped.row === undefined`.
It needs no third argument and puts no `symbol` in the type union, and it degrades in the **safe
direction** under a naive `useLiveQuery: () => undefined` double — such a double reads as *still
loading* (hold the frame) rather than falsely asserting *permanently missing*.

**Neither shipped `dexie-react-hooks` mock needs editing — audited this planning pass.**
`packages/app/test/setlistView.test.tsx` and `packages/app/test/sheet.a11y.test.tsx` both stub
`useLiveQuery: () => undefined`, and `22-PATTERNS.md` warns those files could start rendering the
*missing* branch. They will not, because `resolved` is computed **archive-first** and both files
supply an archive containing show `4001`, so `resolved != null` and neither new branch is reachable
there. **Preserve that ordering:** the pending/missing split must live **inside** the existing
`if (resolved == null)` branch, never above the archive lookup.
`packages/app/test/sheet.a11y.test.tsx` must stay unmodified by this plan.

**Which unmount-driven sheets get converted — owner decision, 2026-08-06.** Three in total:
`DexView`'s trophy case (the `fullscreen` exemplar, **this plan, Task 3**), plus `TrailNodeSheet` and
`WhyDetail` (the bottom-sheet exemplars, **plan 22-10**). The owner escalation rejected shipping four
bottom-sheet openings enter-only against ROADMAP criterion 1's requirement that every bottom sheet
animate down on close, on the grounds that a module comment is documentation, not delivery.
**`PinSheet` x2, `CompareView` x2 and `FriendDetail` x2 remain the documented seam.** Plan 22-10 owns
the final wording of that seam list in `Sheet.tsx` — **this plan must not edit `Sheet.tsx`.**
