# Phase 21 — UI Design Contract

> Visual and interaction contract for **Layout & Layering Foundations** — one owner for the
> bottom-space arithmetic, no installed-PWA dead gap, a structural layer-ordering invariant, one
> UTC-safe full-date format, and the short bottom-tab names. Generated by gsd-ui-researcher;
> verified by gsd-ui-checker.
>
> **This is a consolidation phase, not a new-screen phase.** It ships **zero new screens, zero new
> colors, zero new type roles, zero new z-tiers, and zero new runtime dependencies.** Every token
> below is either **DETECTED** from the shipped Guezzer design system (`packages/app/src/styles.css`
> `@theme`, `packages/app/src/config.ts`) or **DERIVED** from the 44 locked decisions in
> `21-CONTEXT.md` (D-01…D-44). Nothing was re-asked of the user — `21-CONTEXT.md` records
> *"Claude's Discretion: None."*
>
> What this spec adds that does not exist yet: **(a)** the named bottom-space token ladder and its
> two compositions, **(b)** the exact tab and presence label strings, **(c)** the date format and
> its boundary, **(d)** the layering invariant expressed as a structural rule. Those four are the
> contract phases 22–24 build on.

## Spacing Scale

Tailwind v4 default 4px scale — already the app-wide contract (multiples of 4 only). This phase
adds **no new spacing unit**; it removes duplicated *compositions* of the existing ones.

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px (`gap-1`) | Tab icon → label gap (unchanged) |
| sm | 8px | Gap between a lifted FAB and the surface below it (`ExploreFilterFab` `+ 8px`) |
| md | 16px | FAB resting clearance above the chrome reserve; RecapView page-footer bottom padding |
| lg | 24px | Sheet internal section spacing (unchanged) |
| xl | 32px | **Modal-sheet scroll-container bottom padding** — the `+ 32px` term of `--gz-sheet-pad-bottom` (D-07) |
| 3xl | 64px = **`4rem`** | **The tab-bar button-area height** — the one number this whole phase exists to give a single owner (D-04) |

Exceptions:
- **44px minimum tap target** (`min-h-11 min-w-11`) on every interactive element — non-negotiable
  (SHOW-02 venue "one-thumb-in-the-dark" floor, held app-wide). Each of the 5 tabs is `flex-1`
  inside a `4rem` bar, clearing the floor at every supported viewport.
- **112px** (`config.ui.SUGGESTION_STRIP_HEIGHT`) — the fixed, always-reserved SuggestionStrip slot.
  Sized for 2 × `min-h-11` rows with breathing room; **not** on the 4px display scale by intent and
  **not** to be converted to a measured height (D-06 — the 56→112px drift was a wrong constant, not
  a wrong mechanism).
- **`rem` is the source unit for the bar height** (D-04). `4rem` scales with the user's font-size
  setting so the 14px/600 tab labels inside it never clip under enlarged Dynamic Type. The retired
  `64px` literals do not scale and are removed. Everything composed from the owner inherits the
  scaling.
- **Safe-area insets** are composed, never re-derived. `env(safe-area-inset-bottom)` appears exactly
  **once** in the codebase after this phase (§Bottom-Space Token Contract). Top insets keep the
  shipped per-surface `calc(env(safe-area-inset-top) + 12px)` idiom (UX-01/D-01) and are **out of
  scope** for the bottom guard.

## Bottom-Space Token Contract

**The centerpiece of this phase.** Today the bottom arithmetic exists in four notations across 9
files that disagree by one safe-area inset. After this phase there is one ladder.

### Ownership

| Layer | Location | Rule |
|-------|----------|------|
| Numbers | `config.ts` → `config.ui.bottomSpace` | `TAB_BAR_HEIGHT_REM: 4`, `FAB_CLEARANCE_PX: 16`, `SHEET_PAD_BOTTOM_PX: 32`. CLAUDE.md single-config-file rule; unit-testable (D-01). |
| Composition | **one** module, `packages/app/src/layout/bottomSpace.ts` | Writes the numbers + the runtime overlay height to CSS custom properties on the app root. **The only place a bottom-anchored literal or a bare `env(safe-area-inset-bottom)` may appear** (D-01, D-12). |
| Consumption | every surface | Reads `var(--gz-*)`. No consumer composes its own `calc()` string. |

### The ladder

| Custom property | Composition | Consumed by |
|-----------------|-------------|-------------|
| `--gz-safe-bottom` | `env(safe-area-inset-bottom)` | The **single** appearance of the raw `env()`. Never consumed directly by a tab-bar-relative surface; it exists so non-tab-relative surfaces (sheets, pages) still have one owner for the inset. |
| `--gz-tab-bar-h` | `4rem` (from `TAB_BAR_HEIGHT_REM`) | `BottomTabBar` button-area height |
| **`--gz-chrome-reserve`** | `calc(var(--gz-tab-bar-h) + var(--gz-safe-bottom))` | **Tab bar only.** Non-scrolling `<main>`; every `fixed`/`absolute` bottom-anchored surface. Designed to collapse to `var(--gz-safe-bottom)` when chrome hides — Phase 22 flips one source, not every call site (D-16). Phase 21 ships it **pinned to always-visible**: no behavior change, no way to hide yet. |
| `--gz-overlay-inset` | measured px from `useBottomOverlayInset` (`{n}px`) | Feeds the content reserve **only** (D-03) |
| **`--gz-content-reserve`** | `calc(var(--gz-chrome-reserve) + var(--gz-overlay-inset))` | **Scrolling `<main>` only.** Preserves the deliberate `AppShell.tsx:64-78` divergence: non-scrolling routes (orbit stage, constellation) must **not** reserve the overlay inset, because reserving squishes a `flex-1` full-height stage every time a transient banner appears (D-02). |
| `--gz-sheet-pad-bottom` | `calc(var(--gz-safe-bottom) + 32px)` | **Modal-sheet scroll containers.** Deliberately **NOT** tab-bar-relative — a sheet covers the tab bar; it does not sit above it (D-07). Collapses the copy-paste in `Sheet.tsx:104`, `ArchiveBrowser.tsx:379`, `CometTrail.tsx:231`. |
| `--gz-fab-offset` | `calc(var(--gz-chrome-reserve) + 16px)` resting; `calc(var(--gz-chrome-reserve) + 112px + 16px)` while the strip **slot is reserved** | Show-Mode FAB **and** the "Low confidence" weak-fan hint (they must never drift — `show/fabLayout.ts` is the one source for both) |

Naming: the `--gz-` prefix is chosen for **greppability** — the D-12 guard test keys off it, and it
does not collide with the shipped domain-scoped properties (`--show-bg-*`, `--explore-bg-*`,
`--float-*`, `--ripple-*`).

### Two named compositions, not one

`--gz-chrome-reserve` and `--gz-content-reserve` are derived from the same parts and differ by
exactly one term. The divergence is **shipped, deliberate, and now documented** (D-02) — it must not
be "simplified" into a single value.

### The FAB does not move when a strip appears (D-05)

Shipped `fabLayout.ts` takes `stripHasContent` — so **the FAB moves 112px mid-show the instant an
editor suggestion arrives, under a reaching thumb, in the dark.** That violates the founding
"tap targets never move on their own" rule.

**Contract:** `showBottomFabOffset` takes **`stripSlotReserved`**, fed the **same `openerSeeded`
signal that drives `<SuggestionStrip reserveSpace>`** (`ShowView.tsx:489`). Consequences:

- The FAB and the strip slot appear together at the **one** deliberate transition (opener logged),
  and never move again for the rest of the show.
- The Phase-10 `a60d5e2` lift is **preserved, not undone** — the reserved slot height is always ≥
  the rendered row height, so the FAB still clears every rendered suggestion row.
- `stripHasContent` stops being a layout input. It may remain a rendering input inside
  `SuggestionStrip` itself.

### Surfaces converted (D-08, D-09)

| Surface | Today | After |
|---------|-------|-------|
| `AppShell` `<main>` (scroll) | `calc(4rem + env(...) + {n}px)` | `var(--gz-content-reserve)` |
| `AppShell` `<main>` (no-scroll) | `calc(4rem + env(...))` | `var(--gz-chrome-reserve)` |
| `BottomTabBar` | `calc(4rem + env(...))` + `paddingBottom: env(...)` | `var(--gz-chrome-reserve)` + `var(--gz-safe-bottom)` |
| `InstallBanner`, `UpdateToast`, `BackupToast`, `WaveToast`, `BingoCelebration` | Tailwind `bottom-16` (= 64px from the **viewport**; `fixed` ignores body padding) → **overlaps the tab bar by exactly one inset on an installed instance** | `bottom: var(--gz-chrome-reserve)`. `BingoCelebration.tsx:207`'s comment reasoning that `bottom-16` clears the bar is correct in a Safari tab (inset `0`) and **wrong installed** — correct the comment. Include in the FOUND-01 before/after device measurement (D-09). |
| `FabMenu` + `show/fabLayout.ts` | `calc(env(...) + 64px [+112px] + 16px)` | `var(--gz-fab-offset)` (see D-05 above) |

| `NodeSheet:153`, `MapView:468` | bare `env(...)` / `absolute bottom-0` | Audited; converted if tab-bar-relative, else **left with a comment saying why** (D-08) |
| `styles.css:220` `body { padding-bottom: env(...) }` | present | **Removed** — the D-15 lead hypothesis (double-counted inset; mirrors the UX-01 top-inset fix recorded three lines above it). Left/right gutters (`:221-222`) **stay** — they have no per-surface duplicate. If the device measurement contradicts D-15, body keeps it and the guard test whitelists that one line with the measurement as its comment. |
| `BingoPeekStrip` | in-flow, never `fixed` | **Out of scope** — it has no bottom offset to unify. FOUND-02's wording overreached (D-10); recorded so the milestone audit does not read this as unmet. |

### Guard (D-12)

A Vitest source-scan over `packages/app/src` fails if `4rem`, `64px`, or a bare
`env(safe-area-inset-bottom)` appears **anywhere except** `layout/bottomSpace.ts` and `config.ts`.
Bottom-anchored only — `env(safe-area-inset-top)` and `env(safe-area-inset-left/right)` are
untouched and permitted. Precedent: `configMirror.test`, the cover-art budget guard.

**No compatibility shim, no feature flag** (D-13). One commit establishes the owner
byte-identically; surfaces convert in small revertible groups (tab bar + main → FAB family → toast
family). Keeping the old constants alive would recreate the two-systems state this phase exists to
eliminate — and would fail FOUND-02 on its own wording.

## Layering Contract

**No tier is renumbered.** (`ROADMAP.md` §Coverage standing constraint; `REQUIREMENTS.md` §"What NOT
to build".) The ladder in `config.ui.z` is correct; the **nesting** is not.

| Tier | Value | Status this phase |
|------|-------|-------------------|
| `content` | 10 | Unchanged. `ShowView.tsx:176-179` wraps the show column in `zIndex: content` — **this creates a stacking context**, and it is the defect's root. |
| `peek` | 12 | Unchanged |
| `page` | 15 | Unchanged. **WR-01 guard: `page < sheetScrim`** — gains a named test assertion (D-25). |
| `celebration` | 18 | Unchanged |
| `toast` | 20 | Unchanged. Rendered as a **sibling of `AppShell`** (`App.tsx:119-123`) — top level, so it beats a `50` nested inside a `10`. |
| `fabScrim` | 25 | Unchanged. **CR-01 guard: `fabScrim < fab`** — gains a named test assertion (D-25). |
| `fab` | 30 | Unchanged |
| `sheetScrim` | 40 | Unchanged |
| `sheet` | 50 | Unchanged |
| `focusedFab` | 60 | Unchanged — the **deliberate non-modal exception** (D-03/D-26). It survives, by name, with a comment. |

### The invariant is structural, not numeric (D-24)

A pure config-value comparison **passes today despite the defect** and therefore cannot satisfy
FOUND-03. The test asserts:

> **Every surface rendering at the `sheet` tier is portaled to `document.body`,** so its z-index
> competes at the top level rather than inside a nested stacking context.

**Modal-only scope** (D-26), matching FOUND-03's own wording ("open **modal** sheet"). Two
exceptions are carried **explicitly by name, with comments**: the non-modal `NodeSheet`, and the
`focusedFab: 60` lift above `sheet: 50`.

### Fix by portaling, not renumbering (D-21, D-22)

`SearchSheet.tsx:95-103`, `AlbumDetail.tsx:48`, `ArchiveBrowser.tsx:270`, `SetlistView.tsx:120/131`
and `NodeSheet.tsx:150` are hand-rolled (`role="dialog"`, own `zIndex`, **no portal**) and render
inside the `ShowView` `content: 10` context. They gain `createPortal(…, document.body)` — exactly
the pattern `Sheet.tsx:77/90` already ships. They **stay hand-rolled**: migrating them onto the
shared `<Sheet>` primitive is deliberately excluded so Phase 22's animation blast radius stays at 11
surfaces, not 16.

### A portaled node loses its ancestors — re-apply what it loses (D-23)

**This is a venue-regression risk, not a cosmetic one.** `styles.css:27-35` scopes gesture
suppression to `.orbit-stage`, `.action-bar`, `.fab-menu`:

```
touch-action: manipulation;      /* kills double-tap zoom */
overscroll-behavior: none;       /* no pull-to-refresh, no scroll chaining */
user-select / -webkit-user-select: none;
-webkit-touch-callout: none;     /* iOS long-press callout */
```

`SearchSheet` matters most — it is *the* one-thumb, in-the-dark surface, and losing double-tap-zoom
or long-press-callout suppression there is a real SHOW-13 regression. **Apply the needed classes
directly on each portaled root**, and audit each surface for anything else relying on tree position
(focus order, Escape handling).

### Also audit transform-created contexts (D-28)

`transform`, `filter`, `backdrop-filter`, `opacity` and `will-change` on an ancestor create a
stacking context **and** make `fixed` descendants position relative to that ancestor — strictly
worse (mispositioned, not just mispainted). Live instances: `MapView.tsx:213`,
`ExploreBackground.tsx:120/157`, `ShowBackground`, `ExploreFilterFab.tsx:97`. Grep for it; **fix only
what reproduces.**

### Repro harness (D-29, D-27)

A URL flag following the shipped `?mockLatest=1` precedent force-shows a toast so any sheet — **and
the FabMenu** — can be opened over it on demand in a desktop browser. `FabMenu.tsx:120/129` sits at
`fabScrim: 25`/`fab: 30` inside the same `content: 10` column: if the nesting analysis holds, a
`toast: 20` paints over the FAB and eats its taps **mid-show**, which is worse than the sheet case
because it hits the live-logging loop. Reproducible for the Phase 22–24 authors, not just once here.

the **raw string**, never `Invalid Date`. Rename the file to the format-neutral
`packages/app/src/dex/formatDate.ts` now that it houses two formatters; update the two
`formatMonYear` importers (`SongRow.tsx`, `WhyDetail.tsx`). **Not core** — this is presentation, and
core has no display-formatting layer.

(`SongRow.tsx:39`, `WhyDetail.tsx:69`) — "last seen Jan 2025" is the right granularity for a song's
era, and a full date there would imply precision the stat does not carry. **Two vocabularies is
correct:** one for a specific show, one for a song's history.

**Format at the call site** (D-34). `config.ts:1142-1144` composes `{date} · {venue}` and keeps
composing whatever string it is given. Components format before calling — `config.copy` stays free
of presentation logic and the helper stays the single owner.

### Display-only boundary (D-35) — load-bearing

> **A formatted date must never reach stored or exported data.**

Dexie rows, the backup envelope, export filenames, `show_id`/date join keys, and the
`attendanceKey` **unbound** branch (`date:${date}#${sessionId}`) stay **ISO, always**. The date *is*
a join key in the unbound attendance path — a formatted date leaking into stored data would silently
break dex derivation and merge. Same discipline as NAV-02's display-labels-only rule.

### Share-card footer (FOUND-05, D-36/D-37)

The footer `date · venue` line is drawn by `centerText` at a fixed 44px with **no width constraint**
(`shareCard.ts:193`, `shareCard.ts:424`) on a 1080×1350 canvas, while `truncateToWidth`
(`shareCard.ts:252`) and `wrapLabel` already ship in that same file. "Mon D, YYYY" is ~2 characters
longer than the ISO string it replaces, so this change makes an existing overflow risk **worse**.

**Contract:**
- Pass a max width derived from the card margins (**`width * 0.9` = 972px**, the same margin the
  badge row already uses at `shareCard.ts:417`) into both footer draws.
- **Truncate the venue, never the date.** Measure the date + separator first; ellipsize only the
  venue remainder via the existing `truncateToWidth`. The date is what FOUND-05 is about.
- Venue-null path is unchanged (date-only, no truncation possible).
- **Footer baseline check (D-37):** the footer sits at `height * 0.99` with a 44px font — descenders
  may already clip at the card's bottom edge, independent of the date change. Look while producing
  the FOUND-05 card; **fix only if it clips.**

## Accessibility

- **≥44px tap targets** preserved everywhere. Each tab is `flex-1` inside a `4rem` bar (`min-h-11
  min-w-11` retained). The rename shortens labels; it must not shrink hit areas.
- **`rem`-sourced bar height** (D-04) is an accessibility decision: at enlarged Dynamic Type the bar
  grows with its 14px/600 labels instead of clipping them.
- **Two accessible names gain human-readable dates** (D-33): `SetlistView` `aria-label` and the
  ArchiveBrowser unmark-confirm label. VoiceOver currently announces `2026-08-14` as a number
  sequence; after this phase visible and announced text are identical.
- **Presence labels are never blank and never a raw token** (NAV-03/D-41) — an unrecognized token
  resolves to `in the app`. Presence continues to pair the online dot with a visible text label
  (WCAG 1.4.1 — never color alone).
- **Portaling must not cost a11y** (D-23): audit each portaled surface for focus order, focus
  return, Escape handling and `aria-modal` correctness once it is no longer a DOM descendant of its
  trigger. These five surfaces are VoiceOver-verified today; they must still be after.
- **The `focusedFab` exception survives** — it exists so a keyboard/VoiceOver user can reach the
  filter control while a node is focused. It is not a numbering accident.
- **Installed-PWA safe areas**: no bottom-anchored control may land under the home indicator in
  either orientation. This is what FOUND-01's before/after measurement proves.
